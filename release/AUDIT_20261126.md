## 7. 1.5.10：最新审核的阻断项与导入保真

本轮审核基于 `d1e8bc7`。其中一项被判定为阻断：`Wh_ModInit` 要求 `Shell_TrayWnd` 已存在，而 Windhawk 在登录、重启和 Explorer 重启时都先调用 `Wh_ModInit`，此时任务栏尚未创建，模组会拒绝加载。已在 1.5.10 修复：

| 审核问题 | 修复与验证 |
| --- | --- |
| 启动时模组拒绝加载 | 删除 `Wh_ModInit` 中的 `EnsureStartLatchSubclass()` 门禁；subclass 只由 `ClearStartButtonLatch` 在首次需要复位时安装，安装失败仍走原有的同步复位回退。`HookShowStartView` 等失败路径仍清理资源并返回 `FALSE`。 |
| 卸载竞态可重新挂上 subclass | `Wh_ModUninit` 在 `WaitForSingleObject(g_thread, INFINITE)` 之后重新 `FindWindowW(L"Shell_TrayWnd")` 并再次 `RemoveWindowSubclassFromAnyThread`；此时启动器线程已回收，不会再产生新的复位请求。 |
| 导入丢失本机私有覆盖 | 导入脚本在替换数据目录前读取当前 `ui-settings.ini`，仅当四项本机覆盖保存时的 Windhawk 基线仍等于当前主机值时，把 `program`、`winKeyAction`、`shiftWinKeyAction`、`startButtonAction` 的私有值写回新存储；基线已过期则由 Windhawk 值生效。新增 Python 回归覆盖“保留有效覆盖”和“丢弃过期覆盖”。 |
| 后台图标开关位置与 README 不符 | `webIconBackgroundFetch` 从 Power 页移到 Grid 页的 Website icons 分组，补充中文分组名；模组内英文 README 与仓库中文 README 均改为指向该位置及 Windhawk 设置页。 |
